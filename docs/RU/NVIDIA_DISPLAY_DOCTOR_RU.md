# NVIDIA Display Doctor / Heal

[🇬🇧 English](../EN/NVIDIA_DISPLAY_DOCTOR_EN.md) | [🇷🇺 Russian](NVIDIA_DISPLAY_DOCTOR_RU.md)

Модуль реализует ограниченный сценарий из `nvidia-display-restore(8)`:
диагностика пропавшего NVIDIA-модуля после обновления ядра Ubuntu.

В меню `remedia system center` → System добавлен пункт **7) NVIDIA display**.
Внутри него: **1) NVIDIA display doctor**, **2) NVIDIA display heal**.

Команды:

```bash
remedia system nvidia-display doctor
remedia system nvidia-display heal
```

Doctor не требует root и не изменяет пакеты, модули или настройки экрана.
Отчёт содержит ядро, ОС, наличие NVIDIA display hardware, установленные пакеты,
ветку и вариант драйвера, файл модуля для текущего ядра, загруженные nvidia/nouveau,
Secure Boot, соответствующий пакет и кандидата APT.
`nvidia-smi` запускается с ограничением времени 15 секунд только при загруженном
модуле: некоторые установки автоматически вызывают из него `nvidia-modprobe`.
При незагруженном модуле в отчёте указана причина пропуска.

System Doctor включает тот же аудит, но никогда не вызывает Fix или Heal.

Heal сначала выполняет Doctor и симуляцию APT. Если нужен root, используется
штатный код Remedia **42** для повторного запуска через sudo. После повторной
диагностики выводится точный план. Подтверждение — ввод полного имени пакета;
при EOF или другом ответе изменений нет. APT также сохраняет свой запрос
подтверждения. После установки выполняются `depmod -a <текущее ядро>` и
`modprobe nvidia`, затем Doctor запускается повторно.
Команда `fix` выполняет тот же подтверждаемый план без итогового Doctor.

Heal разрешён только если:

- ОС — Ubuntu, NVIDIA display hardware обнаружено;
- установлен ровно один пакет `nvidia-driver-<ветка>[-server][-open]`;
- модуль для текущего ядра отсутствует и не загружен;
- есть установленный пакет готовых NVIDIA-модулей для этой ветки и другого ядра;
- нет установленного NVIDIA DKMS и загруженного nouveau;
- точный пакет для текущего ядра ещё не установлен, и найден кандидат APT;
- симуляция не удаляет пакеты и не меняет другие драйверы, ядра, библиотеки или DKMS.

Версия кандидата закреплена в команде установки. Автоматическая смена ветки
драйвера, отключение Secure Boot, выгрузка модулей, изменение разрешения экрана
и перезагрузка не выполняются. APT update/upgrade также не запускаются.
Если модуль существует, но не загружен, или `nvidia-smi` сообщает NVML mismatch,
Doctor предлагает исследовать ошибки и журнал ядра вручную.

Здоровый драйвер не доказывает наличие Full HD. На GNOME/Wayland проверяйте
режимы в настройках экрана; одного `xrandr` недостаточно. После восстановления
самостоятельно перезагрузитесь в удобное время и повторите Doctor.

Коды Doctor: 0 — исправно/нет NVIDIA; 10 — неполная диагностика; 11 — неизвестная
ветка; 12 — несколько вариантов; 13 — не Ubuntu; 14 — DKMS; 15 — нет признаков
готовых модулей; 16 — нет кандидата; 20 — отсутствующий модуль, доступен план;
21 — модуль существует, но не загружен; 22 — ошибка nvidia-smi; 23 — пакет уже
установлен, но модуль недоступен; 24 — загружен nouveau.
Heal/Fix: 25 — неподходящий план APT; 42 — нужен root; ошибки системных команд
сохраняют собственный код возврата.

Проверка без установки пакетов и загрузки настоящих модулей:

```bash
python3 tests/test_nvidia_display.py
```

Проверки используют временные файлы и подставные системные команды.

Основание: `nvidia-display-restore(8)` и официальная документация Ubuntu:
https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/
